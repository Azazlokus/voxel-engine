# Задача 01 — каркас движка и бесконечный мир

Прочитай `CLAUDE.md` целиком, все правила оттуда обязательны.

## Цель

Запускаемое десктопное приложение: окно, свободная камера, бесконечный процедурный ландшафт
из блоков, который подгружается вокруг игрока в фоне без фризов. Архитектура — по `CLAUDE.md`,
с плагинами и реестрами с первого дня.

## Порядок работы

0. **План.** Перед кодом покажи: дерево крейтов, ключевые трейты и типы (`Plugin`, `App`,
   `Registry<T>`, `BlockId`, `Chunk`, `WorldGenerator`, формат вершины), поток данных
   «генерация → мешинг → GPU». Дождись моего подтверждения.
1. **Workspace и ядро.** `engine_core`: `App`, `Plugin`, этапы, ресурсы и события на `bevy_ecs`.
   `client` запускает пустое приложение из плагинов.
2. **Реестр.** `engine_registry`: `Identifier` (`namespace:path` с валидацией), `Registry<T>`,
   регистрация → заморозка → числовые ID. Тесты: дубликаты, невалидные ID, стабильность ID
   при одинаковом порядке регистрации.
3. **Контент как данные.** `engine_assets` грузит `assets/base/blocks/*.ron`.
   `game_base` регистрирует блоки: `air`, `stone`, `dirt`, `grass`, `sand`, `water` (пока непрозрачная
   или полупрозрачная — на твоё усмотрение, но решение в ADR), `log`, `leaves`.
   Текстуры 16×16 сгенерируй процедурно (шум + цвет) и положи в `assets/base/textures/`.
4. **Мир.** `engine_world`: секция 16³ с палитрой и bit-packing, однородная секция = одно значение,
   колонки чанков, конвертация мировых/чанковых/локальных координат (включая отрицательные!).
   Тесты на всё это.
5. **Генерация.** `engine_worldgen`: трейт `WorldGenerator`, реализация на шуме — холмы, высота
   ±40 блоков, слои grass/dirt/stone, песок у уровня воды, вода ниже уровня моря, редкие деревья
   (дерево не должно обрезаться на границе чанка — продумай). Детерминизм по seed.
6. **Мешинг.** `engine_mesh`: greedy meshing с учётом соседних чанков (грань на границе
   не рисуется, если сосед непрозрачен), вершина 8 байт, ambient occlusion по вершинам.
   Тесты: один блок = 6 квадов; плита 16×16 = 1 квад сверху; два разных блока не склеиваются.
   Бенчмарк `criterion`: мешинг типичной секции.
7. **Рендер.** `engine_render` + `engine_platform`: окно, wgpu, атлас/texture array из реестра блоков,
   пайплайн для чанков, depth buffer, frustum culling, туман на дальности прорисовки.
   Выбор бэкенда через `WGPU_BACKEND`, лог адаптера.
8. **Стриминг чанков.** Вокруг камеры радиус N чанков (настраиваемый, по умолчанию 12):
   задачи генерации и мешинга в `rayon`, сортировка по расстоянию, отмена/игнор устаревших задач,
   выгрузка дальних чанков, лимит загрузок в GPU за кадр. Перемешинг соседей, когда появился новый чанк.
9. **Управление и отладка.** WASD + Space/Shift, мышь (захват курсора, Esc — отпустить),
   колесо — скорость полёта. В заголовке окна: FPS, время кадра, позиция, число загруженных/видимых
   чанков. F3 — переключить wireframe или границы чанков (что проще).
10. **Документация.** README (сборка и запуск под Windows из PowerShell, управление), ADR по ключевым решениям.

## Критерии приёмки

- `cargo build --release` и `cargo run --release -p client` запускают игру.
- `cargo fmt --check`, `cargo clippy --workspace --all-targets -- -D warnings`, `cargo test --workspace` — зелёные.
- Полёт по миру со скоростью ~50 блоков/с без заметных фризов при радиусе 12 на среднем ПК;
  метрики видны в заголовке.
- `game_base` не использует ничего, кроме публичного API движка.
- Добавление нового блока = новый RON-файл + текстура, без правок кода движка. Покажи это,
  добавив блок `base:gravel` последним коммитом.
- Отрицательные координаты работают (нет швов и дыр на осях X=0 и Z=0).

## Вне скоупа этой задачи

Ломание/установка блоков, физика игрока и коллизии, сохранение мира, освещение от источников,
прозрачность с сортировкой, LOD, звук, UI, WASM-моды. Только трейты/границы там, где это
дёшево и очевидно пригодится.

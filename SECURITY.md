# Политика безопасности

## Статус проекта

Воксельный движок в активной разработке, стабильных релизов пока нет.
Поддерживается только ветка `main`.

## Как сообщить об уязвимости

Не открывайте публичный issue для уязвимостей.

Используйте приватный канал GitHub:
[Security → Report a vulnerability](https://github.com/Azazlokus/voxel-engine/security/advisories/new).

В отчёте по возможности: версия/коммит, ОС и GPU-бэкенд (`WGPU_BACKEND`), шаги
воспроизведения, воздействие. Ответ — в течение 7 дней.

## Модель угроз

Движок — десктопное однопользовательское приложение без сети. Актуальные классы проблем:

- **Разбор недоверенных данных.** RON-описания контента, текстуры и (позже) сохранения мира
  могут прийти из мода или чужого мира. Паника на некорректном вводе — баг; порча памяти —
  уязвимость.
- **Код модов.** Мод-API проектируется под будущую изоляцию через WASM (`wasmtime`).
  Нативные моды доверенными не считаются и в поставку не входят.
- **`unsafe`.** Каждый блок обязан иметь обоснование `// SAFETY:` рядом (проверяется в CI)
  и ADR при неочевидности. Нарушение инварианта в `unsafe` — уязвимость, а не просто баг.
- **Цепочка поставок.** Зависимости проверяются `cargo-deny` (advisories, licenses, sources),
  GitHub Actions закреплены по commit SHA, обновления — через Dependabot.

Вне модели угроз: сеть и мультиплеер (отсутствуют), многопользовательские сценарии,
защита от владельца машины.

## Автоматические проверки

| Что | Где |
|---|---|
| Известные CVE и заброшенные крейты | `cargo-deny advisories`, ежедневно по cron |
| Лицензии и источники зависимостей | `cargo-deny licenses` / `sources` |
| Статический анализ кода | CodeQL (`rust`, `actions`), еженедельно |
| Секреты в коде и истории | TruffleHog + GitHub secret scanning с push protection |
| Новые зависимости в PR | `dependency-review` |
| Практики безопасности репозитория | OpenSSF Scorecard, еженедельно |
| Обоснование каждого `unsafe` | job `Проверка unsafe` в CI |

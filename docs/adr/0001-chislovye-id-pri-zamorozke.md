# 0001. Числовые ID выдаются при заморозке, по возрастанию текстового ID

Дата: 2026-10-28
Статус: принято

## Контекст

Блоки, предметы и генераторы регистрируются под текстовыми ID вида `base:stone`.
В памяти и в мешах нужен компактный числовой ID: воксель в секции — это индекс в палитре,
а не строка. Вопрос в том, как и когда числа назначаются.

Требование расширяемости: мод добавляет свой блок, не трогая код движка, и набор
установленных плагинов меняется между запусками.

## Решение

Реестр имеет две фазы. На первой плагины регистрируют контент по текстовым ID,
числовых ID не существует. На второй — `Registry::freeze` — записи сортируются
по возрастанию `Identifier`, и числовой ID становится индексом в этом порядке.

Числовые ID (`RawId`) живут только в памяти текущего запуска. В файлах, RON-описаниях
и в мод-API используются текстовые ID.

## Почему сортировка, а не порядок регистрации

Задача требовала «стабильности ID при одинаковом порядке регистрации». Сортировка даёт
более сильное свойство: ID не зависят от порядка установки плагинов вообще. Это важно,
потому что порядок плагинов — не свойство мира, а свойство конфигурации: достаточно
переставить две строки в `client` или поменять порядок загрузки модов, чтобы при
«стабильности по порядку регистрации» все ID разъехались.

## Следствия

Добавление нового контента сдвигает числовые ID соседей: `base:gravel` встанет между
`base:grass` и `base:leaves`. Поэтому:

- Хардкодить числовые ID нельзя нигде — это и так требование CLAUDE.md, теперь оно
  подкреплено тем, что числа заведомо меняются.
- Сохранение мира (задача 02+) обязано хранить таблицу соответствия текстовых и числовых
  ID вместе с данными чанков и ремапить при загрузке. Для модов такая таблица нужна
  всё равно: мод могли удалить, и его блоки должны превратиться в заглушку, а не в
  случайный чужой блок.

## Альтернативы

**Порядок регистрации.** Проще, но ID зависят от конфигурации — см. выше.

**Хеш текстового ID.** ID стабильны всегда, таблица ремапа не нужна. Отвергнуто:
хеш не даёт плотного диапазона, а плотность нужна — числовой ID используется как индекс
массива в палитре секции и как индекс в texture array.

**Фиксированные ID в описаниях контента.** Автор мода сам назначает число. Отвергнуто:
два мода неизбежно выберут одно и то же число, и конфликт придётся решать вручную.
